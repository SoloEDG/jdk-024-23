# 静水手记

安装：`npm install`

本地启动：`npm run dev`

Docker 启动：`docker compose up --build`，访问 http://localhost:18224。

类型检查：`npm run typecheck`

## 中断续战与恢复边界

刷新或切走页面不再结束垂钓，蓄力、等待、咬钩、搏鱼均可续战：

- **公平代价**：同一竿累计离开的前 60 秒完全暂停；超出部分按真实墙钟时长结算——搏鱼中的鱼恢复体力，浸泡饵在 120 秒计费时长内线性失效，等待/咬钩阶段饵彻底失效则鱼散去并记脱钩。反复短退持续累计，不会刷新免费额度。
- **救援道具**：返回后可在确认弹窗里消耗稳线夹（仅搏鱼、压住张力）或备用饵（恢复浸泡饵效力并缓和局面），每竿各限一次，也可放弃本竿；已耗鱼饵与道具均不返还。确认前弹窗会显示道具库存是否够用，库存不足时按钮禁用。
- **辅助标记**：任意一次救援都会把该竿上岸的鱼标记为 `assisted`，不计入“标准无救援”挑战（`stats.cleanCatches`）。
- **保存节奏**：完整现场（`doc + session`）打包为一份 v2 信封原子写入，普通检查点每秒最多一次；抛竿、救援扣料、上岸、脱钩、清空为关键步骤立即写入。
- **一致恢复边界**：可重放的对抗过程（会话现场）与不可重复的资源结果（背包、图鉴、道具、统计）同信封落盘。输入、救援扣料或上岸若发生在两次保存之间，恢复一律以最后一次成功存档为准：不会因旧现场重新发鱼、不返还已花道具，也不会用下一份存档补救本次关页。
- **最后松手**：离开时不猜测输入状态，恢复后收线一律为未按住，绝不把没记录到的松手还原成长按。
- **异常处理**：救援确认中再关页会先把已发生的离开时长结算进现场再写；写入失败保留旧信封并在顶部标明保存失败；上岸恰逢检查点按上岸步骤立即写。旧版 v1 手记仍按原方式继承资源并从新的一竿开始，不恢复进行中的现场。
